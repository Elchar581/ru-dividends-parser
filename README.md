# Парсер истории дивидендов российских эмитентов

> **In English.** A Python scraper that collects dividend payout history for
> Russian public companies from the MOEX ISS API and two public web sources,
> reconciles what is already paid against what is only announced, and writes
> the result into a multi-sheet Excel workbook. Built to be re-run months later
> without code changes. Package layout, pinned dependencies, disk-cached HTTP
> layer with retries and soft SSL degradation, unit tests for the parsing rules.
> Docs below are in Russian.


Собирает дивидендную историю по 30 тикерам (28 эмитентов) и складывает её в
книгу Excel: **Таблица №1** — общий список акций, далее **28 листов** —
по одному на эмитента.

Ключевое: это не разовая выгрузка. Парсер каждый раз заново опрашивает
источники и сам определяет, что уже выплачено, а что только объявлено.
Запустите его через год или через два — он подтянет всё новое без правок кода.

---

## Требования

* **Python 3.10 или новее** (проверено на 3.13.15). Скачать:
  https://www.python.org/downloads/ — при установке обязательно отметить
  **«Add python.exe to PATH»**.
* Windows (скрипты `.bat` рассчитаны на неё; сам код кроссплатформенный).
* Доступ в интернет к `iss.moex.com`, `smart-lab.ru`, `dohod.ru`.

Зависимости в системный Python **не ставятся** — всё уходит в локальное
виртуальное окружение `.venv` внутри папки проекта.

## Установка

```bat
git clone https://github.com/Elchar581/ru-dividends-parser.git
cd ru-dividends-parser
setup.bat
```

`setup.bat` выполняется один раз и делает всё сам: проверяет версию Python,
создаёт `.venv`, ставит туда зависимости зафиксированных версий из
`requirements.txt` и прогоняет тесты разбора. Если тесты не прошли — окружение
собрано неверно, и скрипт об этом скажет, а не сделает вид, что всё хорошо.

Повторный запуск `setup.bat` безопасен: существующее окружение не пересоздаётся,
зависимости просто доустанавливаются.

### Если что-то пошло не так

| Симптом | Причина и решение |
|---|---|
| `python не найден в PATH` | Python не установлен либо ставился без галочки «Add python.exe to PATH». Переустановите с этой галочкой. |
| `нужен Python 3.10 или новее` | В коде используется синтаксис `X \| None`. Обновите Python. |
| Ошибка с `SSL` / `CERTIFICATE` при установке | Корпоративный прокси подменяет сертификат. Команда для обхода приведена в самом сообщении об ошибке `setup.bat`. |
| Кракозябры в консоли | Консоль не в UTF-8. Скрипты выставляют кодировку сами; при ручном запуске добавьте `set PYTHONIOENCODING=utf-8`. |

## Запуск

```bat
run_daily.bat
```

Или напрямую, если нужны параметры:

```bat
.venv\Scripts\python.exe run.py --tickers SBER,GAZP -v
```

Оба варианта используют Python из `.venv`. Системный `python run.py` тоже
запустится, но только если зависимости стоят глобально — на это не полагайтесь.

Результат: `output\Дивиденды_РФ_ГГГГ-ММ-ДД.xlsx`, лог прогона — `output\run.log`.
Полный прогон по 30 тикерам занимает около минуты.

## Что попадает в файл

### Лист «Таблица №1 Общая» (Часть 1 из ТЗ)

№ · Тикер · Компания · Тип акции · Полное наименование с MOEX · ISIN ·
Уровень листинга · Ссылка на сайт эмитента · Председатель СД / крупнейший
акционер · Число выплат в выборке · Последняя цена · Ближайшая отсечка ·
Ближайший дивиденд · Ожидаемая доходность · Статус ближайшей выплаты ·
Ссылка на лист с историей · Замечания сбора.

Названия, ISIN и уровень листинга подтягиваются с MOEX при каждом прогоне.
Ссылка на сайт и председатель СД лежат в `config\issuers.json` — открытых
API с этими данными нет, поэтому поля справочные и правятся руками.

### 28 листов по эмитентам (Часть 2 из ТЗ)

Все шесть колонок из ТЗ плюс служебные:

| Колонка | Откуда |
|---|---|
| Период / год учёта | smart-lab (приоритет), dohod.ru |
| **Дата появления информации** | dohod.ru; если он ещё не проставил — дата первого обнаружения выплаты парсером |
| **Последний день покупки** | smart-lab; если нет — расчёт по торговому календарю MOEX |
| **Дата закрытия реестра** | smart-lab + dohod.ru |
| **Размер дивиденда** | smart-lab + dohod.ru (расхождения помечаются) |
| **Цена акции на закрытие** | MOEX ISS, официальная цена закрытия |
| **Дивидендная доходность, %** | считается как дивиденд / цена |
| Статус | вычисляется от сегодняшней даты |
| Дата цены, Источники, Примечания | служебные, для проверки |

Привилегированные акции лежат на листе своего эмитента: `SBER` + `SBERP` — один
лист, `BSPB` + `BSPBP` — один лист. Поэтому 30 тикеров дают 28 листов, как в ТЗ.

### Лист «Журнал сбора»

Пустой журнал = все источники отработали штатно. Строки в нём означают, что
источник сменил разметку или был недоступен — эти тикеры стоит проверить руками.

---

## Три статуса выплаты

| Статус | Что значит | Цвет строки |
|---|---|---|
| Выплачен | реестр закрыт, выплата состоялась | без заливки |
| **Объявлен (предстоящий)** | совет директоров утвердил, отсечка впереди | зелёная |
| Прогноз (не объявлен) | оценка аналитиков, официального решения нет | жёлтая |

Статус не хранится в файле — он **вычисляется от даты запуска**. Одна и та же
выплата сегодня «предстоящая», а через месяц в новой выгрузке «выплаченная».
Прогнозы отделены от объявленных намеренно: выдавать оценку ресурса за решение
совета директоров нельзя.

---

## Как это ловит будущие выплаты

1. **smart-lab держит отдельную таблицу «Ожидаемые дивиденды».** Как только
   совет директоров даёт рекомендацию, строка появляется там — и в ближайшем
   прогоне приезжает в Excel со статусом «Объявлен (предстоящий)».
2. **Верхней границы по датам нет.** Фильтр только снизу (`--start`), всё
   будущее проходит насквозь.
3. **Последний день покупки для будущей отсечки считается сам** — по торговому
   календарю MOEX, а для дат за горизонтом календаря по рабочим дням.
4. **Реестр первого обнаружения** (`output\first_seen.json`). Официальную дату
   объявления dohod.ru проставляет с задержкой в недели. Поэтому парсер ведёт
   собственный журнал: при каждом прогоне запоминает увиденные выплаты, и для
   новой фиксирует дату, когда она впервые появилась в источниках. Именно это
   даёт колонку «дата появления информации» по свежим рекомендациям.
   Файл накапливается между прогонами — **не удалять**.
   Он же ловит изменение уже объявленного размера: в лог пойдёт строка
   «по выплате на ... размер изменён с ... на ...».

Чтобы механизм работал, парсер должен запускаться регулярно (см. ниже).
Разовый запуск через два года всю историю подтянет, но датой обнаружения
для новых выплат будет день этого запуска.

## Работа по расписанию

`run_daily.bat` рассчитан на Планировщик заданий Windows. Он сам вызывает
Python из `.venv` по абсолютному пути, поэтому не зависит от того, с каким
`PATH` планировщик запускает задачу:

```
Планировщик заданий -> Создать простую задачу
  Имя:        Парсер дивидендов
  Триггер:    Ежедневно, 20:00
  Действие:   Запуск программы
  Программа:  C:\Users\Elchar1\div-parser\run_daily.bat
  Рабочая папка: C:\Users\Elchar1\div-parser
```

Или из PowerShell одной командой:

```powershell
schtasks /Create /TN "Парсер дивидендов" /TR "C:\Users\Elchar1\div-parser\run_daily.bat" /SC DAILY /ST 20:00
```

Каждый прогон кладёт файл с датой в имени, поэтому история выгрузок сохраняется.

## Настройка списка эмитентов

Всё в `config\issuers.json`, код трогать не нужно.

```json
{
  "no": 5, "ticker": "SIBN", "name": "Газпром нефть",
  "share_type": "Обыкновенная",
  "issuer_key": "SIBN",          // объединяет ао и ап в один лист
  "smartlab_page": "SIBN",       // у ап своей страницы нет: SBERP -> SBER
  "dohod_slug": "sibn",
  "moex_aliases": [],            // старые коды на случай переименования
  "site": "https://ir.gazprom-neft.ru/",
  "chairman": "Председатель СД — ..."
}
```

Добавить эмитента — дописать объект в массив. Убрать — удалить объект.
Сменился председатель — поправить строку.

**`moex_aliases`** — страховка от переименования тикера биржей (так `TCSG`
стал `T`, а `YNDX` — `YDEX`). Парсер сначала проверяет основной код на MOEX,
и если тот больше не торгуется, берёт псевдоним и пишет об этом в лог.

## Источники данных

| Источник | Что берём | Почему он |
|---|---|---|
| **MOEX ISS** `iss.moex.com` | цены закрытия, торговый календарь, наименование, ISIN, уровень листинга | официальное API биржи, без ключа и регистрации |
| **smart-lab.ru** | отсечка, последний день покупки, период, размер, **ожидаемые выплаты** | единственный с готовой таблицей объявленных будущих выплат |
| **dohod.ru** | **дата объявления дивиденда**, отсечка, размер | единственный из доступных публикует дату объявления |

Цены берутся с MOEX, а не с агрегаторов: `LEGALCLOSEPRICE` — официальная цена
закрытия основной сессии, по ней и считают доходность. Сверено вручную:
SBER на 17.07.2025 — 325,92 ₽ и у MOEX, и у smart-lab.

Два источника перекрывают друг друга по размеру и дате отсечки. Если они
разошлись больше чем на 2%, парсер **не выбирает молча правильный**, а пишет
расхождение в колонку «Примечания» — решение остаётся за человеком.

## Что сделано для живучести

Через два года сайты будут выглядеть иначе. Заложено вот что:

* **Колонки ищутся по названию заголовка, а не по номеру.** Источник вправе
  переставить колонки, добавить новую или сменить CSS-класс — разбор устоит.
* **Ни одной зашитой даты выплаты.** Всё вычисляется от текущей даты.
* **Падение источника не роняет прогон.** Не ответил один — работаем на
  втором, замечание уходит в «Журнал сбора». Не ответили оба — тикер помечен
  красным, остальные 29 собраны.
* **Смена режима расчётов** (T+2 до 31.07.2023, T+1 после) вынесена в одну
  константу `T1_MODE_SINCE` в `divparser/moex.py`.
* **Кэш на диске** — повторный прогон не бомбит сайты и работает за секунды.
* **Офлайн-тесты** проверяют разбор без сети:

  ```bat
  python tests\test_parsing.py
  ```

  Если данных нет, а тесты зелёные — проблема на стороне сайта, а не в коде.

## Что нужно проверить перед отправкой заказчику

1. **Колонка «Председатель СД / крупнейший акционер»** в Таблице №1 —
   справочные данные из `config\issuers.json`, актуальны на 04.09.2026.
   Составы советов директоров меняются ежегодно; сверьте с сайтами эмитентов.
2. **Лист «Журнал сбора»** — если он не пуст, по перечисленным там тикерам
   данные неполные.
3. **Колонка «Примечания»** на листах эмитентов — там помечены расхождения
   между источниками и случаи, где цена или дата рассчитаны, а не получены.

## Известные ограничения

* **Дата объявления по свежим выплатам.** dohod.ru проставляет её с задержкой.
  До этого момента в колонке стоит дата первого обнаружения парсером, о чём
  прямо написано в «Примечаниях». Точность здесь тем выше, чем регулярнее
  запускается парсер.
* **Официальный первоисточник (e-disclosure.ru) не подключён.** Портал
  раскрытия отдаёт сообщения через постбэки ASP.NET и требует отдельного
  идентификатора на каждого эмитента; надёжно парсить его без браузерной
  автоматизации не выходит. Если дата объявления станет критичной по всем
  выплатам — это следующий шаг: новый класс в `sources.py` по образцу
  существующих.
* **Корпоративный прокси с подменой TLS-сертификата.** Парсер это переживает:
  один раз пишет предупреждение в лог и продолжает без проверки сертификата.
  Чтобы предупреждение убрать, укажите корневой сертификат компании:
  `set REQUESTS_CA_BUNDLE=C:\path\to\corp-root.pem`
* **Смена типа акции.** Если эмитент выпустит новый класс акций, его нужно
  дописать в `config\issuers.json` руками.
